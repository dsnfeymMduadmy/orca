# Orca API — справочник для модулей и приложений

Модуль/приложение никогда не вызывает функции ядра напрямую по имени — вместо этого
ядро при запуске передаёт указатель на `orca_api_t` (таблица функций, стабильный ABI).
Это позволяет менять реализацию ядра, не пересобирая модули.

Заголовок: `firmware/OrcaKernel/api/orca_api.h`

## 1. Точка входа модуля/приложения

```c
#include "orca_api.h"

int orca_app_main(const orca_api_t* api) {
    api->log->info("hello", "Привет из модуля!");
    while (!api->task->should_stop()) {
        api->task->sleep_ms(100);
    }
    return 0;
}

void orca_app_stop(void) {
    /* опционально: освобождение своих ресурсов перед остановкой */
}
```

Обязательные экспортируемые символы: `orca_app_main`. `orca_app_stop` — опционален.

## 2. Манифест (`module.json` / `app.json`)

```json
{
  "name": "esp_link",
  "type": "module",
  "version": "0.1.0",
  "entry": "module.orca",
  "api_version": 1,
  "author": "you",
  "description": "UART-мост к ESP8266/ESP32",
  "icon": "icon.png",
  "permissions": ["uart", "gpio"]
}
```

Поля:
- `type`: `module` | `app`.
- `api_version`: должна совпадать с `ORCA_API_VERSION` в прошивке, иначе загрузчик
  откажет в запуске (защита от несовместимости ABI).
- `permissions`: декларативный список подсистем, к которым обращается код — используется
  UI для показа пользователю и в будущем для runtime-проверок (см. TASKS.md).

## 3. Группы функций `orca_api_t`

| Группа      | Указатель        | Назначение                                      |
|-------------|------------------|--------------------------------------------------|
| `log`       | `api->log`       | Логирование (info/warn/error) в системный лог     |
| `task`      | `api->task`      | sleep, should_stop, yield — кооперация с планировщиком |
| `gui`       | `api->gui`       | Примитивы рисования, виджеты, события ввода       |
| `storage`   | `api->storage`   | Открыть/прочитать/записать файл через VFS (SD/QSPI/EEPROM) |
| `gpio`      | `api->gpio`      | Доступ к "открытым" GPIO-пинам расширения          |
| `uart`      | `api->uart`      | Работа с UART-портами, выделенными под модули      |
| `spi`/`i2c` | `api->spi/i2c`   | Шины для внешних устройств                         |
| `system`    | `api->system`    | Информация об устройстве, время, батарея           |
| `ipc`       | `api->ipc`       | Обмен сообщениями между модулями/приложениями      |

Полные сигнатуры — см. `orca_api.h`. Версия таблицы фиксируется `ORCA_API_VERSION`;
при добавлении новых функций — только в конец структуры (не ломать ABI).

## 4. Сборка модуля

См. `tools/module_sdk/` — шаблон Makefile собирает модуль как `.orca`
(частично слинкованный ELF32, `arm-none-eabi-gcc -r`) под Cortex-M7 (soft-float/hard-float —
должно совпадать с ядром, см. `getting_started.md`).

## 5. Жизненный цикл

1. `orca_app_main(api)` вызывается в отдельной FreeRTOS-задаче.
2. Модуль должен периодически проверять `api->task->should_stop()` и корректно завершаться —
   иначе по таймауту задача будет принудительно убита (и залогировано предупреждение).
3. Модули типа `module` обычно живут в фоне (например, мост к ESP), `app` — обычно
   GUI-приложение с собственным экраном, останавливается при выходе пользователя в меню.
